Details/Edit Screen Template

One screen per record type, with a View mode and an Edit mode. Every record workspace (Quality Event, NCR, MRB, CAPA, SCAR) is built this way, from the shared classes on the Theme page.

Status never changes in Edit mode: it only moves through the workflow buttons.

Rules

  • Each field appears once on the screen. If it’s in the key fields, it isn’t repeated in a card.
  • No numbered section badges; the card titles are enough.
  • Labels come from the field’s name, never a placeholder (“labelProduct”).
  • Dates through DateFormat: MM/dd/yyyy, “MM/dd/yyyy HH:mm” where the time matters.
  • Measurements: requirement and actual side by side (app-panel-info, app-panel-danger), with the difference spelled out.
  • Empty optional fields show nothing, not “-” or “N/A”. A card with nothing to show isn’t shown.
  • Closing rules are shown as Closure readiness, so the user can see why Close isn’t available yet.

Building it in OutSystems

  • One screen with an IsEditMode local variable (default False) and a local copy of the record for editing.
  • Each field is an If on IsEditMode: an Expression with app-value, or the input. The label and container (app-field app-field-stack) sit outside the If, so nothing moves when the mode changes.
  • The header has two button groups, each in an If: the View buttons and the Edit buttons.
  • Edit copies the record into the local variable and sets IsEditMode. Cancel discards the copy. Save runs the form’s validation, then the save server action, then returns to View and refreshes the record.
  • An optional Edit input parameter opens the screen straight into Edit mode (for “New” or a link from a list).
  • No edit form below the details and no second copy of the details below the form: the mode switches the same cards.

The list screen

  • Title with a one-line description; Export, then New (primary) on the right.
  • Four KPI cards that each open the list filtered (app-kpi).
  • Search and the common filters in one row, More filters for the rest.
  • Table (app-table): the record number as a link, title with material underneath, status and severity badges, then the columns people sort by. Rarely-needed columns become filters.
  • Row actions: Open and More as app-icon-link. A clock flags records with overdue actions (BR-014).

What changes from today’s NCR screens

  • Detail and edit are one screen; the edit form no longer has the detail view repeated below it.
  • NCR number, status, quality event, material, lot and supplier appear once instead of two or three times.
  • The page title is the record, not “NCR & Containment Workspace”.
  • Status labels are readable: the lookup’s Label (“QA Triage”), not its Id (“QaTriage”). Pill colors follow the status colors below.
  • Severity colors only for High and Critical.
  • One date format; the stepper fits the width; the separate Workflow card is gone.
  • Validation Rules became Closure readiness, with live checks.
  • List: one primary button, consistent NCR numbers (NCR-2026-00143), Responsible Department moved to the filters.

Proposed classes and tokens

The mockups need a few things the app’s guide doesn’t have yet. They’re in assets/app.css, marked PROPOSED:

  • app-pill with no variant is the neutral (grey) pill, for Draft and Cancelled.
  • --app-danger-light, --app-success-light, --app-warning-light, --app-neutral-light: pill and panel backgrounds.
  • app-steps and app-step-dot: the stepper’s container and circle.
  • app-kpi-label, app-kpi-value, app-kpi-note: the parts of a KPI card.
  • --app-menu-background, --app-brand-navy, --app-brand-amber: the KT2i navy side menu with an amber active marker, taken from the landing-page mockups.
  • app-hero, app-hero-title, app-hero-accent: the navy welcome band on the home dashboard and the sign-in screen.
  • app-icon-badge: an icon in a tinted square, for the module cards on the home dashboard.

The side menu, top bar, tabs and inputs in the mockups stand in for OutSystems UI widgets (mock-* classes); they aren’t app classes.
