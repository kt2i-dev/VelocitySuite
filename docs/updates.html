What’s new or different in the standard, newest first. Check here before building or reviewing a screen.

11/16/2026

  • Theme: the design conventions. The rule: new screens use the shared app-* classes only, and any gap gets a new shared class, not a one-off. Also where the clean-up stands (only the NCR detail and edit screens follow the pattern so far), the layout recipe (MainContent, one card per topic, a grid in each card, label and value rows), the shared classes with what each is for, the tokens, the screens not to copy from, known gaps, and how to ask for a new class.
  • Button standard: OutSystems UI’s btn for secondary actions and btn btn-primary for the main action, nothing custom. btn-delete is dropped: Delete is a plain btn that asks for confirmation. Row actions are app-icon-link.
  • Custom widgets: each block lists the shared classes it’s built from.
  • Review checklist is up: styling, layout and fields, buttons, dates and status, behavior, and stylesheet checks.
  • First screen mockups: the NCR list and the NCR workspace in View and Edit, built with the shared classes, in the KT2i navy, on the demo scenario’s NCR-2026-00143.
  • Details/Edit Screen Template: one screen per record type with View and Edit modes: the anatomy, what changes between modes, the rules (each field once), how to build it in OutSystems, the list screen, what changes from today’s NCR screens, and a few proposed classes and tokens.
