Review checklist

Check your screen against this before handing it off. Each line points to the standard it comes from.

StylingLayout and fieldsButtonsDates, status and iconsBehaviorIf you changed the stylesheet

Styling · Theme

  • Every widget is styled with shared app-* classes only (and btn for buttons). No screen-prefixed class (ncr-, cc-, mrb-…), new or copied.
  • Nothing was copied from a legacy screen: only the NCR detail and edit screens follow the pattern.
  • Style properties hold class names only: no hex colors, no pixel values, no inline styles.
  • If you touched a screen that still uses a legacy family, it’s migrated to app-* in this change.
  • Anything the shared classes didn’t cover was asked for as a new shared class, not written as a screen rule.

Layout and fields · Layout recipe

  • The screen uses LayoutSideMenu, with its content in MainContent inside app-page or app-page-wide. No per-screen width or padding rules.
  • One card per topic, with a grid inside each card.
  • Record screens: app-split with main and side columns; each section an app-card app-card-sm app-stack with an app-row heading and an app-grid app-cols-N body.
  • Each field is an app-field app-field-stack with its label. In View mode values show as text (app-label / app-value), not as disabled inputs.
  • Detail and edit are one screen with an edit-mode flag, laid out as the Details/Edit Screen Template: each field appears once, the same cards switch to inputs in Edit mode.
  • The screen works at tablet and phone widths: grids collapse, nothing scrolls sideways except tables.

Buttons · Button standard

  • Every button is btn or btn btn-primary, with its Phosphor icon and label from the Button standard. No custom button classes.
  • One btn-primary per screen or section. Delete is a plain btn that asks for confirmation.
  • Common buttons come from the button blocks; Save, Save Draft and Submit stay in the form and show “Saving…” while they run.
  • Buttons sit where the placement table says: header actions in app-actions, More (⋯) for the rest, Cancel left of Save, row actions as app-icon-link.
  • Unavailable actions are disabled with the reason as a tooltip; actions the role can never use are hidden.

Dates, status and icons · Custom widgets

  • Every date goes through DateFormat: MM/dd/yyyy, blank when null.
  • Status and severity go through StatusBadge (app-pill variants); lifecycles through WorkflowStepper. No screen draws its own pill or stepper.
  • Icons are Phosphor 2.0 names that resolve in the app. No SVG data URIs.
  • Lists use app-table; the record number links to the record.

Behavior · Quality Event & Corrective Action Management

  • Status only changes through the workflow server actions, never by editing the field.
  • Delete is for Draft records only and confirms, naming the record.
  • Rejecting, reopening and requesting information ask for a comment or reason.
  • Changes are written to the activity history (AuditLog).
  • Any AI suggestion needs a person to Accept it before it applies.

If you changed the stylesheet · Theme

  • The braces balance, including inside @media blocks.
  • No new literal colors, no new !important (except to override an OutSystems UI default, with a comment), no new screen-prefixed class.
  • No new SVG data URIs or external URLs.
  • The affected screens were checked in the browser.
