Theme

The design conventions every Velocity Suite application shares: one stylesheet, one set of app-* classes and --app-* tokens, and the rules for using them. A fix to a shared class fixes every screen that uses it.

Decisions

  • Layout: left side menu (OutSystems UI’s LayoutSideMenu) on every screen except sign-in. Not the top bar the specs and most mockups show.
  • Dates: MM/dd/yyyy everywhere, through the DateFormat block.
  • Icons: Phosphor 2.0, regular weight. Names are on the Button standard.
  • Font: Inter, through --app-font, loaded from the app’s own resources rather than Google Fonts so it works offline.
  • Buttons: app-btn with app-btn-primary, app-btn-outline or app-btn-danger. See the Button standard.

Principles

  • One shared vocabulary. Every screen is styled with app-* classes and --app-* tokens. No per-screen class families such as ncr-, cc- or mrb-.
  • Style by class, never inline. A widget’s Style property only holds class names. No hex colors or pixel values in widget properties.
  • Layout from the shared layout classes or the widgets’ own layout modes. No rules scoped to one screen to force widths (such as :has(.my-page)): use app-page or app-page-wide.
  • Avoid !important. Allowed only to override an OutSystems UI default, with a short comment saying what it overrides.
  • Change the shared class, not the screen. If three screens need the same tweak, it goes in the shared layer.
  • Colors come from tokens, such as var(--app-accent), never literals.
  • No new SVG data URIs or external URLs in the stylesheet. Add them as app resources so they work offline.

How to choose

  • Record or detail screen: app-page-wide, then app-split with a main and a side column. Each section is an app-card app-card-sm app-stack, with an app-row heading and an app-grid app-cols-N body.
  • A field: an app-field app-field-stack container holding the label and the input. In read-only mode, show the value as text with app-label and app-value, not as a disabled input.
  • Status chips: app-pill with a variant. If the color depends on data, pick the variant with an If expression in the Style property (or use the StatusBadge block, which does this for you).
  • Something missing: add one shared app-* class to the stylesheet, document it here, and use it. Don’t create a screen class.

Detail and edit screens

Detail and edit screens are being merged into one screen per record type, with an edit-mode flag: View shows values as text, Edit shows the inputs, and the header buttons switch with the mode.

NCRDetailScreen is the pilot. It’s only partly done and can’t replace the edit screen yet, so it isn’t the template to copy until stage 2 is finished. The Details/Edit Screen Template page will document its structure then.

Legacy classes, being migrated

These families are still screen-specific and will be removed as their screens move: cc-, rc-, cw-, capa-, ncr-, mrb-, main-, kpi-, adv-, event-.

  • Don’t copy them to new screens.
  • When you touch one of those screens, migrate it to app-* classes in the same change.

ncr- is still listed because the NCR list screen uses it; the NCR detail and edit screens no longer do.

Before saving the stylesheet

  • The braces balance, including inside @media blocks.
  • No new literal colors, no new !important, and no new screen-prefixed class.
  • The affected screens were checked in the browser.
