Theme

The design conventions every Velocity Suite application shares: one stylesheet, one set of app-* classes and --app-* tokens, and the rules for using them. A fix to a shared class fixes every screen that uses it. The stylesheet carries the same guide in the APP DESIGN SYSTEM GUIDE comment at its top.

The rule

New screens use the shared app-* classes only. No new per-screen class families (xyz-), ever. If the shared classes don’t cover something, the gap gets a new shared class (see Asking for a new class), not a one-off.

Nothing in the stylesheet enforces this, so it’s checked in review: see the Review checklist.

Where things stand

  • In place: the app-* classes and --app-* tokens; buttons on plain OutSystems UI btn / btn btn-primary (79 buttons on 8 screens, no custom button classes); the guide comment at the top of the stylesheet; 143 dead rules removed.
  • Only the NCR detail and edit screens fully follow the pattern. They have no screen-specific style families left. Every other screen still uses its old per-screen classes, including MRB, CAPA and the NCR list.
  • The stylesheet still has !important rules and legacy families waiting to be removed.

Decisions

  • Layout: left side menu (OutSystems UI’s LayoutSideMenu) on every screen except sign-in. Not the top bar the specs and most mockups show.
  • Dates: MM/dd/yyyy everywhere, through the DateFormat block.
  • Icons: Phosphor 2.0, regular weight. Names are on the Button standard.
  • Font: Inter, through --app-font, loaded from the app’s own resources rather than Google Fonts so it works offline.
  • Buttons: OutSystems UI’s btn for secondary actions and btn btn-primary for the main action. Nothing custom. See the Button standard.

Principles

  • One shared vocabulary. Every screen is styled with app-* classes and --app-* tokens (plus OutSystems UI’s btn classes).
  • Style by class, never inline. A widget’s Style property only holds class names. No hex colors or pixel values in widget properties.
  • Layout from the shared layout classes or the widgets’ own layout modes. No rules scoped to one screen to force widths (such as :has(.my-page)): use app-page or app-page-wide.
  • Avoid !important. Allowed only to override an OutSystems UI default, with a short comment saying what it overrides.
  • Change the shared class, not the screen. If three screens need the same tweak, it goes in the shared layer.
  • Colors come from tokens, such as var(--app-accent), never literals.
  • No new SVG data URIs or external URLs in the stylesheet. Add them as app resources so they work offline.

Layout recipe

  1. Screen content goes in MainContent of the layout, inside app-page (or app-page-wide for record screens).
  2. One card per topic: app-card app-card-sm app-stack, with an app-row heading. Record screens put the cards in app-split: app-split-main for the record, app-split-side for status, related records and the assistant.
  3. A grid inside each card: app-grid app-cols-N, never side-by-side containers with fixed widths.
  4. Label and value rows in the grid. Edit mode: an app-field app-field-stack holding the label and the input. View mode: the value as text with app-label and app-value, not a disabled input.
  • Status chips: app-pill with a variant. If the color depends on data, pick the variant with an If expression in the Style property (or use the StatusBadge block, which does this for you).

Detail and edit screens

Detail and edit screens are being merged into one screen per record type, with an edit-mode flag: View shows values as text, Edit shows the inputs, and the header buttons switch with the mode.

NCRDetailScreen is the pilot. It’s only partly done and can’t replace the edit screen yet, so don’t copy its current structure. The target is the Details/Edit Screen Template and its NCR workspace mockup.

Legacy: don’t copy from these screens

Every screen except the NCR detail and edit screens still uses old per-screen classes: MRB, CAPA, the NCR list and the rest. Don’t copy markup or classes from them.

The families being removed: cc-, rc-, cw-, capa-, ncr- (NCR list only), mrb-, main-, kpi-, adv-, event-.

  • Don’t use them on new screens.
  • When you touch one of those screens, migrate it to app-* classes in the same change.

Known gaps

  • Multi-line text areas have no shared class yet.
  • .app-form-footer .btn still overrides the button size in form footers. Whether it stays is undecided.
  • Some !important rules and the legacy families above are still in the stylesheet.

Until a gap has a shared class, ask rather than writing a screen rule.

Asking for a new shared class

  1. Check the shared classes and the custom widgets first: most needs are a combination of existing classes.
  2. Ask the theme owner, with the screen, what’s missing, and what you tried.
  3. If it’s agreed: add one app-* class to the shared layer (tokens only, no screen name), add it to the guide comment at the top of the stylesheet and to this page, then use it.

Before saving the stylesheet

  • The braces balance, including inside @media blocks.
  • No new literal colors, no new !important, and no new screen-prefixed class.
  • The affected screens were checked in the browser.
