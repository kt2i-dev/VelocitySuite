Button standard

One icon and a label for every action, the same style and place on every screen of every Velocity Suite application. Generated by tools/build_buttons.py: edit that, not this page.

Two styles

SubmitEditDeleteTrace Lot

OutSystems UI’s own button classes, styled by the theme (see the Theme). No custom button classes, and nothing else in the button’s Style property.

  • btn: outlined, for every secondary action, Delete included.
  • btn btn-primary: filled, for the main action. One per screen or section: the step that moves the record forward (Submit, Save, Issue SCAR, Approve, Apply). Our standard
  • Delete is a plain btn with the trash icon. It sits apart from the other buttons and always asks for confirmation, naming the record.
  • Row actions are icon links, not buttons: app-icon-link (Open, More), and app-icon-link-danger for a row’s Delete.
  • A button that can’t be used yet stays visible but disabled, with the reason as its tooltip (“Available after submission”, “MRB-2026-00081 is still awaiting approval”). A button the user’s role can never use is hidden.

Icon names are Phosphor 2.0, the app’s icon library: pick them by these names in ODC Studio’s icon picker. Use the regular weight everywhere. The AI mentor review found about 120 icon references that don’t resolve in the app; replace each with the name from this table.

The button blocks

  • One block per common button (ButtonEdit, ButtonCancel, ButtonDelete, ButtonAssign, ButtonApprove…), each with the icon, label and class built in, so the same action looks the same everywhere.
  • Inputs: IsEnabled (Boolean, mandatory) and ExtendedClass (Text, optional: shared app-* classes only). ButtonNew and ButtonAddAction also take Label.
  • Event: Clicked, no parameters. What happens goes in the parent’s handler.
  • Not blocks: Save, Save Draft and Submit stay plain buttons inside the form, because they have to run the form’s validation. They use OutSystems UI’s Button Loading (“Saving…”) and are disabled until the call finishes.
  • Workflow buttons (Create NCR, Request MRB, Close Event…) are plain buttons with the icon and class above. Each calls one server action that checks the rule and moves the status, so status only changes through these actions.

Same pattern as the LifeView button blocks.

How this differs from the mockups

  • Fewer header buttons. The mockups put seven to ten outlined buttons in a row on every workspace, sometimes with two primaries (Save and Submit for Closure). Here: one primary, up to three others, then More.
  • No red buttons. The Administration mockup draws Cancel in red; here Cancel, Reject and Delete are all plain btn.
  • No disabled “after submission” row. The Create Quality Event mockup shows Create NCR, Place Hold and Trace Lot greyed out under the form; here they appear in the header once they can be used.
  • The icons follow the mockups’ choices where they had one.
